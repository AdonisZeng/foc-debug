# 排查卡：代码实现类坑（保护/消抖计数器 · 无符号运算 · 类型宽度）

> 定位：保护判据、消抖计数、时间戳等**纯软件机制**出问题时查这张卡。特征是
> "电机、传感器、硬件全部正常，保护却误触发/判据失灵/数值瞬移"，且调参数
> 无效——因为根因不在参数，在代码的运算语义。
> 条目来自高压风扇电机实测调试（见 `motor-profiles/hv-fan-motor.md`）。

## 坑1：无符号计数器带衰减分支，计数为 1 时减大步长下溢回绕，保护误触发且阈值调多大都无效

**适用标签**：`软件判据` `无符号计数器` `消抖/保护` `阈值调参无效`

**现象**：基于无符号计数器消抖的保护（"连续 N 拍超限即触发"类：缺相、堵转、
过流确认等）在**无故障工况下随机误触发**；把阈值（计数窗口）调大**无效**，
调到任何值仍触发；触发呈偶发性，与负载/转速无明显规律。实测案例：缺相保护
`erro_cnt`（uint16，零流带 ±50 码，带内 +1 / 带外 -2）在健康电机上随机触发
fault=10 锁死（触发即 restart_count 置锁死值，断电才能恢复），窗口调到
12000 拍（≈1s）仍复现。

**物理根源**：计数器采用"带内 +1 / 带外 -2"的非对称更新（衰减快于累加，
意图快速清历史）：

```c
cnt = (in_band) ? (cnt + 1) : (cnt > 0 ? cnt - 2 : 0);
```

`cnt` 是 uint16。+1 单步累加意味着计数必然经过 1；而带外衰减分支的条件只判
`cnt > 0`，**cnt=1 时 1-2 在无符号运算下回绕为 65535**。65535 大于任何 uint16
阈值，下一次裁决拍必超限 → 保护触发。三个叠加因素让它必然发生：
1. "进带 1 拍即出带"的时序常见——低速过零带穿越、噪声毛刺边沿，恰好落在
   下溢窗口；
2. +1/-2 更新下计数奇偶交替，cnt=1 是高频驻留态，不是罕见态；
3. 下溢后 65535 衰减回 0 需 32768 个带外拍（12kHz 下 ≈2.7s），期间几乎必然
   被裁决节拍采样到。

**判断方法**：
1. **触发瞬间读计数器**：fault 触发时刻用调试器/打印读该计数器，看到接近
   65535 而非"略超阈值"→ 下溢实锤（"阈值调大仍触发"是旁证：65535 大于
   任何 uint16 阈值，调参永远追不上回绕值）。
2. **静态审查递减形态**：全代码搜形如 `? (x - N) :` 的计数器递减，核对三
   要素——无符号类型、步长 >1、递减条件未保证 `cnt >= 步长`。三者齐备即
   存在下溢路径，与是否已触发无关。
3. **奇偶推演**：带内 +1 / 带外偶数步衰减的更新律下，计数奇偶交替，枚举
   "进带 1 拍 → 出带"的拍序即可构造出下溢，不需要等复现。

**处理思路**：
- **递减前钳位**（推荐，对任意步长安全）：`(cnt >= STEP) ? (cnt - STEP) : 0`；
- 或衰减步长改 1（1-1=0）——但正确性依赖"步长恰为 1"，将来把衰减调快
  （步长 >1）会复发，治标；
- 修复后回归两点：a) **同形态代码成组出现**（如三相各一路计数器），逐行
  同步核对，只改一行必漏；b) 为压误报而临时调大的阈值/窗口应**恢复设计
  值**——下溢修掉后"调多大都触发"的现象消失， enlarged 窗口反而拖慢真实
  故障的检出时间。

**交叉引用**：`hall-sensor.md` 坑3——同为无符号回绕，方向相反：那边是
uint16 时间差回绕让判据**永不成立**（漏保护），本坑是下溢回绕让保护
**误触发**（误动作）。排查"判据行为与设计完全相反"类问题时，先查无符号
运算语义再怀疑物理。
